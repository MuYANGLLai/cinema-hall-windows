# cinema-hall Windows 端使用说明

本文只讲**怎么用**。为什么这么做、放弃了哪些路线，见 `docs/Windows端技术方案.md`；
Phase 0 的实测底稿见 `docs/Windows-Phase0.md`。

当前版本：`0.1.0`（W1–W6 落地）。**还没有线上影厅**（RTC 在 W7），现在是一个
「本地播放器 + 本地影片库」的桌面应用。

---

## 1. 交付形态

一个 zip，解压即用。解压后目录长这样：

```text
cinema-hall\
  cinema-hall.exe        ← 双击这个
  vlc\                   ← libvlc.dll / libvlccore.dll / plugins\（随包分发）
  使用说明.md            ← 本文件
  data\                  ← 首次启动时自动创建，**不随 zip 分发**
```

`data\` 是用户数据，不在发布包里：里面是影片库索引、设置、日志、单实例锁。
发布包带一个别人的 `data\` 会让你「带着别人的影片库首次启动」，所以打包脚本
显式排除了它（`desktopApp/build.gradle.kts` 的 `releaseZip` → `exclude("**/data/**")`）。

**不需要**在机器上安装 VLC：`vlc\` 跟 exe 同级，程序只认这个位置。

---

## 2. 第一次用（解压后照着做）

1. 解压 zip 到一个**可写**目录。可以是中文名、带空格的路径（例如
   `D:\我的 影片\cinema-hall`）—— 这一条是门禁项，已实测。
2. 双击 `cinema-hall.exe`。窗口标题 `cinema-hall · Windows`。
   首次启动会先出现 **「设备激活」** 页（见下面第 2 条补），激活之后才会进主界面，
   并在 exe 同级创建 `data\`。
3. 左侧点 `影片库` → 在「根目录」区点 `选择目录…`，选一个存电影的目录
   （或用输入框粘贴路径后点 `添加`）。可以有多个根目录，程序会**递归**扫。
4. 点 `开始扫描`。列表会先**秒出**（快扫只读文件名与大小），时长在后台补；
   右上角进度显示 `解析时长 123/500`，全部完成后变成 `完成：500 部`。
5. 回 `首页`，在「最近可播」里点一部片，或直接点 `打开文件` 选单个视频。
   控制条在画面**下方**（不是浮在画面上）：`播放` / 暂停 / 进度条 / 音量。
6. 想退出：关窗口会直接退出程序；托盘图标（`cinema-hall`）右键有 `显示主窗口` /
   `退出`。

> **第 2 条补：设备激活（第一次必做）**
>
> 生产信令开着账号校验（`AUTH_MODE=required`），**没有激活的设备连不上服务器**。
> 所以第一次打开是这一页，填三项：
>
> | 字段 | 填什么 |
> | --- | --- |
> | 入场码 | 发给你包的人给的那串（8 位，形如 `ABCD-EFGH`；`-` 和空格可以不填，大小写都行） |
> | 设备名 | 这台电脑在账号设备列表里的名字，默认取计算机名，可以改 |
> | 昵称（可选） | 房间里显示的名字；留空由服务器生成「影友XXXX」 |
>
> 点 `激活`。成功后会直接进主界面，并把凭据写进 `data\credentials.json`（按服务器地址
> 分开存），**以后不用再输**。失败会在按钮上方给出原因，常见几种：
>
> - `入场码格式不对` —— 位数或字符不对（不含 `0/O/1/I/L`）。
> - `入场码已过期 / 已用完 / 已被撤销` —— 让对方重新发一个。
> - `连不上服务器` —— 服务器地址或网络问题。点 `服务器地址` 可当场改（默认
>   `wss://101.133.234.226:8443/ws`）。
> - `这台设备已被移除` / `账号已被停用` —— 联系发码的人。
>
> 换服务器（自己在局域网搭一个）也在这个页面改，改完需要重新激活。
> 想彻底换账号：删掉 `data\credentials.json` 再启动，就会回到激活页。

> 为什么控制条在下面：Compose 的 `SwingPanel` 里塞的是 AWT 重量级 Canvas，
> 任何 Compose 控件叠在它上面都**看不见**。这是 Phase 0 的结论，不是审美选择。

## 3. 快捷键

| 按键 | 作用 |
| --- | --- |
| `空格` | 播放 / 暂停 |
| `←` / `→` | 后退 / 前进 10 秒 |
| `↑` / `↓` | 音量 +5% / −5% |
| `Ctrl+O` | 打开文件对话框 |

快捷键走窗口级预览（`onPreviewKeyEvent`），所以不用先点画面才有焦点。

## 4. 界面里有什么

窗口是**无边框**的（2026-11-07 起）：自绘标题栏（右上角最小化 / 最大化 / 关闭，
与 Windows 系统同款）+ 八向拖边缩放。全屏只是把窗口铺满显示器，不再切窗口样式，
所以进/出全屏都不会黑一下。

**拖动 / 缩放 / 最大化一律由 Windows 自己做**（用户 2026-11-07 拍板「选 A」）：
外观还是无边框 + 自绘标题栏，但拖标题栏、拖四边四角、双击最大化、拖到屏幕顶部最大化、
左右贴边各占半屏、`Win`+方向键 —— 全是系统行为，用的是系统那套手感与动画。
最大化铺满的是**工作区**（不盖任务栏）。右上角三键也是 Win11 的样子：
46×32 方块、悬浮时最小化/最大化铺一层白色 12%、关闭键铺 `#C42B1C` 实心红并把叉转白、
按下比悬浮更暗一档且**松手才触发**、光标保持默认箭头。
**字形直接用 Windows 自己的图标字体**（`Segoe Fluent Icons`，取不到才退 `Segoe MDL2 Assets`），
所以和系统窗口里那三颗**逐像素一致**（实测横杠 10×1、方框 10×10、叉 10×10，墨迹量也对得上）。
真机万一出现拖不动，用 `--native-frame=0` 启动就退回自绘那一套（见 §6）。

- `首页`：只有一张 `影厅` 卡（宽度是窗宽 1/5）。播放器不在这里。
- `影厅`：左边是画面（常驻，未连接时也是同一块画面），右边从上到下三张卡 ——
  `房间成员`（成员 / 控制 / 状态 / 麦，自己那行名字高亮）、`通话`（开关在标题右边，
  两路音量：麦克风输入 / 接收）、`影片`（`片库` 选片、`清除影片`）。房间号与
  「⧉ 复制」在顶部。
- 图标一律**自绘纯色**（`DesktopIcons.kt` 的 `AppIcon` / `PlayerIcon`）：不用 emoji、不用字体字形，缩放与主题色都跟着走。
- **弹窗**一律**无边框**（`AppDialogWindow`）：跟主窗口同一套自绘标题栏，可拖、可拖边缩放。
  弹窗的拖动/缩放同样交给 Windows；它没有最大化（双击标题栏不会放大）。
- **窗口四角是圆角**（Win11 原生 `DWMWA_WINDOW_CORNER_PREFERENCE`，主窗口与弹窗都有）：
  由系统按它的圆角半径 + 抗锯齿去裁，阴影也是系统的。最大化时系统按设计给直角。
  ⚠️ 弹窗内容**不许**用 `clip(圆角)` 再铺底色（0.1.22 用户报「四角有纯白半圆」就是这么来的）：
  圆角外那块 Compose 就不画了，露出的是窗口自身的 AWT 白底，叠上系统的圆角弧正好是一块白半圆。
  底色必须铺**直角矩形**，圆角只交给 DWM 裁（描边可以是圆角的，弧线外面已经被底色填满）。
- **进 / 退全屏是即时切换**（不闪、不黑）：窗口矩形一步到位，界面在下一帧重排。
  全屏与还原用 F11 / Esc / 控制条右端那颗按钮。
  ⚠️ 2026-11-08 想做「像 Windows 最大化那样自然放大」，三条路都实现并实测过，
  在这个技术栈上都不可用，所以这一版没有动画（细节见 `Main.kt` 里 `applyBounds` 的注释）：
  ① 快照缩放：`Robot` 与 `PrintWindow` 都拿不到 Compose/libVLC 的 GPU 画面，
     过渡会变成「一块黑方块放大」；
  ② 逐帧改窗口尺寸：Compose 追不上，整段过渡全黑（12 步、5 步、软件渲染都试过）；
  ③ 暗场遮罩：已于 0.1.20 试用并被否掉。
- **快速拖边缩放的白边已经大幅减少**（2026-11-08）：
  ① 窗口的背景擦除改成主题色（`WM_ERASEBKGND` + 每次尺寸变化主动填一版）；
  ② Compose 给视频窗格包的那层默认白底改成画面底色；
  ③ 组件树里 `#F0F0F0` 的容器统一改深。
  实测「整窗发白」与「接缝处发白」都已消失，拖边时也不会再露窗口后面的内容
  （垫纯洋红窗体实测 0 像素）。
  ⚠️ 还剩一条：**快速拖动窗口边缘时，新拉出来的那一条（实测一个步长，约 25px）仍会闪一下白**；
  影厅页拖边时，播放器与右侧面板的接缝处也会闪同样一条。
  原因：窗口矩形已经变大、而 Compose 的这一帧还没画完 —— 那一条在 GPU 合成的画面上是空白，
  AWT 这一层关不掉（把绘制后端换成 OpenGL 能让白条帧从 22/44 降到 4/42，但那个后端下
  截屏抓不到 GPU 画面，全屏过渡的底片会变成全黑，所以没有默认打开）。
  环境变量 `CINEMA_RENDER_API=OPENGL`（或 `DIRECT3D` / `SOFTWARE`）可以现场对比三个后端。
- **窗口最外那一圈 1px 的浅色边框已去掉**（2026-11-22 定论，`NativeFrame.DWMWA_BORDER_COLOR`）：
  0.1.17 把拖动/缩放交给系统时给窗口补了 `WS_CAPTION | WS_THICKFRAME`，DWM 因此把它
  当成带框窗口，在最外沿画了一条 1px 线（默认色是近白的浅灰）。它画在我们所有绘制**之上**，
  所以改窗口底色没用。**用户报的「拖动边缘发白」「全屏之后屏幕有一条白描边」都是它**：
  全屏时窗口铺满显示器，这一圈正好落在屏幕四边。
  实测（同一段拖动，28 帧）：默认每帧最外 2px 约 185 个亮像素，去掉后 0～8 个。
  以后要 A/B 复核，用环境变量 `CINEMA_DWM_BORDER=default|none`（`white` / `red` 可以
  把那圈线直接标出来看位置）。
- **悬浮控制条**：鼠标在画面上动一下，控制条从画面底部浮出来；**1.3 秒没操作自动收回**（全屏里也一样，包括视频正在播的时候）。
  它是一块跟随画面的独立窗口（`PlaybackOverlay`），所以能真正压在视频上。
  万一那块窗口起不来（个别远程桌面），控制条会自动退回画面下方，功能不减。
  **窗口最小化之后它不会再冒出来**（旧版会：最小化后鼠标在桌面上划过画面原位置，控制条会自己跑到桌面上）。
- **字幕**：在右侧边栏 `影片` 卡里选（`关闭` / `字幕 1 · 英语` / `字幕 2 · 中文` …，当前那条用主色标出）。
  片子里**没有内封文字轨时整行不显示**（与安卓端一致）。悬浮控制条里不再放字幕选择器。
- `影片库`：按分类分块（一个分类一张卡，卡内一行横向封面）。**点封面是「选中」**，不是跳去播放；选中后顶部出现 `播放` / `移动到…` / `改名` / `移除`（`播放` 只对单片可用，也可以从封面右上角的 `⋯` 菜单里选「在影厅播放」）。可加分类 / 改名 /
  批量移动 / 移除 / 手动添加文件；封面是**从视频里抽帧**生成的。
- `设置`：日间模式、默认音量、防休眠、`账号`（改昵称 / 设备列表 / 恢复码 / 退出登录）、
  诊断（程序目录、数据目录、libVLC、扫描阶段）。

## 5. 数据与日志

都在 exe 同级的 `data\` 里（开发态是仓库里的 `desktopApp\data\`）：

| 文件 | 内容 |
| --- | --- |
| `data\library.json` | 根目录列表 + 时长缓存（按「大小 + 修改时间」建键） |
| `data\settings.json` | 主题、音量、防休眠、上次播放、窗口尺寸 |
| `data\logs\app.log` | 运行日志（含每次时长探测失败的具体原因） |
| `data\app-default.lock` | 单实例锁；`--profile=b` 会另建 `app-b.lock` |

想从零开始：**退出程序**后删掉 `data\library.json`（只删这一个文件也会保留设置）。
`settings.json` 坏掉不会让程序打不开，会回落到默认值。

日志里的这条是正常的，不是故障：

```text
direct3d11 vout display error: SetThumbNailClip failed: 0x800706f4
```

每成功探测一部片的时长，探测播放器会建一次视频输出，D3D 就报一次这个错。
它**不计入** `failed`，也不影响播放。

播放相关的诊断（`[vlc] surface attach…`、`[vlc] event playing`、`[vlc] event
lengthChanged=…`）也都写在 `data\logs\app.log` 里。打包后的 exe 是 GUI 程序、
没有控制台，所以**排障一律看日志文件**，不要指望屏幕上能看到输出。

## 6. 命令行参数（排障 / 脚本用）

正常使用不需要这些参数。

```text
--audio-helper         采集子进程（W7 用；本轮只预留分支，不参与产品流程）
--profile=b            同一台机器上的第二个实例（单实例锁按 profile 分；
                       凭据也随之分开：data\credentials-b.json）
--open=<path>          启动即选片
--no-autoplay          选片但不自动播放
--exit-after=<sec>     跑 N 秒后自动退出
--screenshot=<path>    退出前抓一张窗口截图
--hover-center         配合 --screenshot：截图前把**悬浮控制条**叫出来并等它画出
                       第一帧（截图脚本按不了鼠标，不叫这一下拍不到它）
--fullscreen-blink=<ms> 启动 N 毫秒后进全屏、再过 3 秒退出。给自动化验「全屏过渡
                       不闪」用的（按键注入在本机不可靠：一次 F11 会收到两次 KeyDown）
--native-frame=0       关掉「窗口拖动/缩放/最大化交给 Windows」，退回自绘那一套。
                       真机上出现「拖不动 / 拉不动」时用它启动，其余功能不变
--dump-tree            启动 3.5 秒后把 AWT 组件树（含各层底色）打一行到日志。
                       排查「拖边闪白」这类底色问题时用
环境变量 CINEMA_RENDER_API=DIRECT3D|SOFTWARE|OPENGL
                       切换 Compose 的绘制后端（默认交给 Skiko 自己选）。
                       拖边白条、远程桌面花屏这类问题可以换一个后端现场对比；
                       ⚠️ OpenGL 下 `Robot` 抓不到 GPU 画面，全屏过渡会退化成一整块黑
环境变量 CINEMA_DWM_BORDER=default|none|white|red
                       DWM 画在窗口最外沿那 1px 边框的颜色。默认（不设）= `none`，
                       也就是去掉。`default` 是系统默认色（近白的浅灰，就是那条白边），
                       `white` / `red` 可以把它标出来看位置。只用于 A/B 复核
--add-root=<dir>       添加一个影片根目录（写进 library.json）
--scan                 添加后立刻扫描，打印一行统计并退出
--measure-root=<dir>   用临时库（data\measure.json）扫一遍该目录并打印统计
--signal-endpoint=…    临时改信令地址（不改 settings.json）。默认 wss://101.133.234.226:8443/ws
--activate=<入场码>    启动前先把激活做完（走产品同一条激活逻辑；码不写日志）
--device-name=<名字>   配合 --activate：设备名
--nickname=<名字>      配合 --activate：昵称
```

> `--signal-endpoint` 的优先级最高：`--signal-endpoint` > `settings.json` > 内置默认。
> 自检参数（`--room-test` / `--session-test`）也用它，语义没变。

例：不开界面量一遍扫描性能

```powershell
.\cinema-hall.exe --measure-root="D:\我的 影片"
```

打印：

```text
[measure] root=... phase=DONE found=500 probed=500 failed=0 fast=59ms probe=39645ms total=39739ms skippedExt=0 skippedHidden=0 skippedSystem=0
```

- `fast` = 快扫（列片、拿文件名与大小）耗时，列表可交互的时间点；
- `probe` = 后台补时长耗时；命中缓存时为 `0ms`；
- `failed` = 时长解析失败数，**每一片的失败原因都在 `data\logs\app.log` 里**。

`--audio-helper` 现在单独跑起来是「打开麦克风、往 stdout 写裸 PCM、父进程 stdin
EOF 就自杀」。**这不是功能**，只是打包脚本要验证「同一个 exe 能自举出采集进程」
这条分支存在。W7 接 RTC 时才会真正用它。

## 7. 本机实测读数（2026-11，Windows 11 / 32 核）

语料：500 个 939 KB 的视频文件，分在 10 个目录里（`cat0/` … `cat9/`，各 50 个）。

| 场景 | 读数 |
| --- | --- |
| 冷缓存扫描 500 部（开发态） | `found=500 probed=500 failed=0 fast=59ms probe=39645ms total=39739ms` |
| 冷缓存扫描 500 部（**打包态 zip 解压后**） | `found=500 probed=500 failed=0 fast=59ms probe=41264ms total=41361ms` |
| 热缓存重扫 500 部 | `found=500 probed=500 failed=0 fast=60ms probe=0ms total=92ms` |
| 4 个样本片（含 1 个坏文件） | `found=4 probed=4 failed=1 fast=6ms probe=596ms` |
| 起播到出画 | `[vlc] surface attach after 200ms: ok size=1196x665`，`event playing` |
| 播放 15 秒后的状态 | `playing=true position=15151 duration=52209 ready=true` |
| 同机两个实例（打包态，中文+空格路径） | A `18:00:25.800 event playing` → B `18:00:30.809 event playing` → A 退出时 `playing=true position=20151`（**重叠 15 秒都在播**） |

坏文件那一条不是 bug：那个 `sample-5s.mp4` 只有 `mdat` 没有 `moov` 原子，
libVLC 报 `avcodec demux error: Could not open`，日志里写明「播放器进入 STOPPED
（文件打不开）」。**一个坏文件不会拖慢整轮扫描**：探测在 400 ms 内认输。

时长探测是**一次性**成本：第一次扫 500 部约 40 秒（后台进行，列表已经能点），
之后重扫是 92 ms（全部命中缓存）。换机器、换盘、文件名改了不影响缓存命中，
只有「大小或修改时间变了」才会重探。

## 8. 常见问题

**双击没反应 / 窗口一闪就没了**
看 `data\logs\app.log` 最后几行。最常见的两个原因：exe 所在目录**不可写**
（比如在 `C:\Program Files` 下解压），或 `vlc\` 目录被删了。

**`诊断` 页显示 `可播放：否：未找到 libVLC…`**
确认 `vlc\libvlc.dll` 与 `cinema-hall.exe` 是**同级**（不是 `vlc\vlc-3.0.21\`）。
也可以设环境变量 `CINEMA_VLC_DIR=<vlc 目录>` 指过去。

**启动后提示「已有实例在运行」**
单实例是按 profile 的锁（`data\app-<profile>.lock`）。要同机开两个窗口，
第二个用 `cinema-hall.exe --profile=b`。上一个实例异常退出留下的锁不会卡住启动。

**有几部片没有时长**
去 `data\logs\app.log` 搜 `时长探测失败`，后面写着原因。缺 `moov` 的残缺文件、
正在下载的半截文件、掉线的网络盘都会出现在这里；这些片子仍能列出来，只是没有时长。

**第一次扫描很慢**
40 秒 / 500 部是冷缓存的一次性成本，列表在 59 ms 时就已经能列片了。如果几百部片
要几分钟，多半是机械盘随机读或网络盘 —— 时长解析对每部片都要读一次文件头。

**播放时机器不休眠，但我想要它休眠**
`设置` 里关掉 `播放时阻止系统休眠`。这是按 W3 要求默认开启的。

**片子放完以后，进度条回到 0:00、按钮变回 `播放`**
这是现在的行为：片尾触发 libVLC 的 `stopped`，播放器把状态复位，再点 `播放` 从头放。
v1 没有「已看完/重播」这类结束态 UI（影片库里的「已看完」标记是另一件事）。

**没有托盘图标**
部分会话（远程桌面、无桌面 shell）里 `SystemTray` 不可用，程序会跳过安装并在
日志里写 `本机不支持系统托盘，跳过`。不影响其它功能。

**开麦后红字仍写「本机没有接入音频采集」**
先看版本：exe 的 `ProductVersion`（属性 → 详细信息）必须 ≥ **0.1.3**。
`0.1.2` 漏了一条装配：影厅页一打开就会先取一次「当前链路」（界面订阅它的状态），
那条**提前造出来的链路没有音频上行**，而协调者随后认领的正是它 —— 于是房间里这条链路
天生没有麦克风可推。`0.1.3` 把「界面先取」与「协调者来要」收敛成同一个带采集的装配，
并用 `DesktopModuleAudioUplinkTest` 钉住它；`--session-test=a` 那行结尾打了 `uplink=true`。

装的是 0.1.3 及以上仍然报红字时按这两条分：① 面板上按钮是 `关闭麦克风`（说明意图已经是开）
而红字不动 ⇒ 采集子进程起不来，看系统麦克风是否被别处独占 / 隐私设置里本应用是否被禁；
② 按钮仍是 `开启麦克风` ⇒ 那次点击没落到链路上，重开影厅页再点一次，把 `data\logs\app.log`
最后 20 行抄回来上报。

**`本机发送 - · 收到 - 包` 一直不变**
`0.1.4` 之前这**两个数永远不会变**：它们来自 `getStats` 快照，而桌面这一侧没有任何东西
会去取快照（Android 至少还有 ⑦ 面板的「刷新统计」键）。`0.1.4` 起每秒采一次，
所以「在发 / 在收」应当肉眼可见地在动。若 0.1.4 上仍是 `-`，说明这一秒里一次快照都没落地，
把 `data\logs\app.log` 最后 20 行抄回来。

**能听到对方，但对面听不到我 / 我这边没声音（`0.1.4` 起的分诊）**
看面板上的三样东西，它们各自对应完全不同的成因：

| 现象 | 含义 | 下一步 |
|---|---|---|
| `收到` 在涨，但一句都听不见 | 包到了、放不出来 | 看提示是否为「写不进扬声器」；查默认输出设备、是否被独占、是否静音 |
| `收到` 一直是 `-` 或 `0` | 对端根本没往这条链路发 | 让对端在 `④ 房间成员` 里确认在线、且在它那台把麦克风打开 |
| 对端 `收到` 一直是 `0`，本机 `发送` 在涨 | 本机的包在发，但对方没收到 | 换一条路径试（房间里另一台），排除单条链路的问题 |

`0.1.3` 及以前**两人以上**的房间还有一条独立的缺陷：桌面把所有链路共用一个
`WebRtcBackend`，而它的 `pc / 音轨 / 播放设备 / sink` 都是单实例状态 —— 第二个成员
建链就会把前一条的音频接管掉，于是「安卓之间正常、和 Windows 两边都没声」。
`0.1.4` 改成**每条链路一份 backend**（原生工厂仍是进程级单例），两人房与三人房都适用。

## 9. 自己打包

在仓库里（需要 JDK 17、Gradle wrapper）：

```powershell
cd D:\AI\minimax\cinema-hall-L3
$env:JAVA_HOME='C:\Program Files\Java\jdk-17.0.1'
.\gradlew.bat :desktopApp:releaseZip --console=plain
```

产物：`desktopApp\build\dist\cinema-hall-windows-0.1.0.zip`。

- 中间产物在 `desktopApp\build\dist\cinema-hall\`（`stageRelease` 的 Sync 目录）；
- libVLC 来源用 `-Pcinema.vlcDir=<目录>` 指定，默认
  `D:/AI/minimax/_spike/third_party/vlc-3.0.21`；
- zip 里**不含** `data\`，且 `isPreserveFileTimestamps=false` /
  `isReproducibleFileOrder=true`，同样输入打出来的包可复现；
- zip 里只有**一个**顶层目录 `cinema-hall\`（`into("cinema-hall")`）。少了这一层，
  解压时 exe 与 `vlc\` 会摊进你当前所在目录。

⚠️ **别往 jpackage 的元数据里放非 ASCII**。`desktopApp/build.gradle.kts` 里
`description` 故意写成英文：Compose 插件把参数写成 UTF-8 的 `@args.txt`，Windows 上的
jpackage 按**系统代码页**读它，本机（GBK）一遇到中文就崩，报错只有一句
`Input length = 1`。换到开了「Beta: Use Unicode UTF-8」的机器又能过 —— 这种「看机器
脸色」的失败最难查，所以宁可让 Windows 属性页显示英文。真需要中文元数据时，在跑
Gradle 前设 `JAVA_TOOL_OPTIONS=-Dfile.encoding=UTF-8` 可以让它过，但这等于给打包加了一条
隐式前提，不推荐。

开发态直接跑（不用打包）：

```powershell
.\gradlew.bat :desktopApp:run --console=plain --args="--open=D:\片\某片.mp4"
```

开发态的数据目录是 `desktopApp\data\`，libVLC 按
「`vlc\` → `third_party/vlc-3.0.21` → `CINEMA_VLC_DIR`」的顺序找。
